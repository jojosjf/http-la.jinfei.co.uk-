## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 做什么 | 2D 像素风、回合制、方格战棋的机器人 SRPG。核心循环：地图移动 → 选武器 → 敌方选反击/防御/回避 → 战斗演出 → 结算气力/经验/资金 → 敌方回合 → 间章改造 → 下一关。 |
| 最大前提 | **不能用高达 / 魔神 Z / 盖塔等版权机体与角色。** 机体、驾驶员、剧情全部原创，否则无法公开发布。系统玩法本身不受版权保护，可以放心对标。 |
| 用什么做 | **推荐 Phaser 3 + TypeScript + Vite**（网页游戏，直接挂在 la.jinfei.co.uk 下；想出桌面版再用 Tauri 打包）。备选 **Godot 4**（如果明确要上 Steam 卖桌面版）。详见第 2 节。 |
| 谁来做 | 你 = 制作人 / 主策划 / 剧本主笔；Claude Code = 全部程序 + 数据表 + 工具链 + 占位美术 + 自动化测试；**像素美术师 = 必须另找真人**（整个项目最大的瓶颈和成本）；音乐 = 外包或 CC0 素材，音效可自制。详见第 4 节。 |
| 做多大 | 三档：① 垂直切片（1 张图能打完一整关，约 3–4 周）→ ② Demo（序章 + 10 关，4–6 个月，美术是关键路径）→ ③ 完整版（30+ 关、分歧路线、隐藏要素，1 年以上）。**先做 ①，再决定 ②。** |
| 先做什么 | 下周即可开始：Claude 搭工程骨架，用色块占位美术把「移动 → 攻击 → 反击 → 演出 → 敌方回合 → 胜利」整条链跑通；你同步写 12 台己方机体 / 驾驶员的设定和第 1 关剧本。 |

## 1. 对标分析：F 完结篇有哪些系统，我们做哪些

| # | 系统 | F 完结篇原作表现 | MVP 做？ | 技术难度 | 备注 |
|---|---|---|---|---|---|
| 1 | 方格地图与地形 | 方格地图；平地 / 森林 / 山地 / 市街 / 基地 / 海 / 宇宙等，各给命中、回避、伤害修正；基地和母舰内回复 HP/EN | ✅ | 低 | Tiled 画图导出 JSON |

## 2. 技术选型

### 2.1 候选方案对比

| 方案 | 优点 | 缺点 | 适合 | 结论 |
|---|---|---|---|---|
| **Phaser 3 + TypeScript + Vite** | 纯代码、开源免费；网页包最小，直接部署到你的域名；Claude Code 可以写 100% 代码并用 Playwright 自动试玩截图；Tiled 地图原生支持 | 没有可视化场景编辑器；桌面版需额外用 Tauri/Electron 打包 | 网页优先、程序由 AI 承担的小团队 | **推荐** |
| **Godot 4 (GDScript)** | 开源免费；2D 工具完整（TileMapLayer、动画、UI）；一键导出 Win/Mac/Linux/Web/手机；社区有 Tactical RPG 模板 | 网页包约 9 MB (gzip) 且 Safari/iOS 支持差；编辑器操作较多，Claude 在云端无法打开编辑器验证画面 | 目标是 Steam 桌面版 | 备选 |
| **SRPG Studio / SRPG Studio EX** | 无需编程即可做 SRPG，自带素材和战斗动画编辑器；EX 版 2025-10 公布 Steam 页面，分辨率提升并兼容旧版 | 付费；默认是火纹式骑士剑魔法，气力 / EN 弹数 / 精神 / 换乘 / 母舰等 SRW 系统要靠 JS 插件硬改；日文为主 | 不想写代码、接受火纹底子 | 不推荐做 SRW 类 |
| **SRC (Simulation RPG Construction)** | 日本老牌 SRW 风自制引擎，系统天然就是 SRW 式 | 最后稳定版 2010 年，仅 Windows，闭源，无法商用发布 | 仅作参考 | 不用，但**它的数据格式是很好的设计参考** |
| **Unity** | 商业成熟 | 2D 像素非强项，许可证和体积都重 | — | 不用 |

### 2.2 推荐技术栈细节

| 项目 | 选择 | 说明 |
|---|---|---|
| 引擎 | Phaser 3 (最新 3.x) | WebGL/Canvas 自动切换，像素完美缩放 `pixelArt: true` |
| 语言 / 构建 | TypeScript + Vite | 热重载、类型检查、打包静态文件 |
| 内部分辨率 | 480×270（16:9）或 320×240（原作 4:3 味）| 整数倍放大；需要你拍板 |
| 地图格 | 32×32 px | 机体地图图标 32×32 |
| 战斗立绘 | 128×128（LL 尺寸 160×160） | 精灵图集 (texture atlas) 打包 |
| 头像 | 64×64，每人 3–4 表情 | |
| 字体 | 缝合像素字体 Fusion Pixel 12px (OFL-1.1 开源，中日韩齐全) | 2026-05 仍在更新 |
| 地图编辑 | Tiled（免费开源）→ JSON | 地形属性直接写在 tile 自定义属性里 |
| 数值表 | Excel / Google Sheets 维护 → 脚本转 JSON（含 schema 校验） | 机体 / 驾驶员 / 武器 / 精神 / 地形 / 强化零件 |
| 事件脚本 | JSON/YAML 描述的简单指令流（对话、增援、胜败条件、BGM 切换、说得） | 后期可升级成 DSL |
| 测试 | Vitest（数值公式单测）+ Playwright（自动跑一局 + 截图） | 本云端环境已装 Chromium，Claude 可自己跑 |
| 存档 | IndexedDB + 导出 / 导入 JSON 文件 | 防止浏览器清缓存丢档 |
| 发布 | Vite build → 静态文件 → la.jinfei.co.uk / GitHub Pages / itch.io；桌面版 Tauri | |
| 像素绘图 | Aseprite（付费，约 $20）或免费的 Pixelorama / LibreSprite / Piskel | 美术师自选 |
| 音乐 / 音效 | FamiStudio、Bosca Ceoil（免费）；jsfxr / Bfxr / ChipTone 做音效 | |

### 2.3 推荐仓库结构

```
/
├─ docs/            设计文档、美术规格书、数值表说明
├─ src/
│  ├─ core/         纯逻辑：网格、寻路、战斗计算、气力、精神（不依赖 Phaser，可单测）
│  ├─ data/         机体 / 驾驶员 / 武器 / 地形 / 精神 JSON + schema
│  ├─ scenes/       Phaser 场景：标题 / 地图 / 战斗演出 / 间章 / 对话
│  ├─ ui/           面板、菜单、字体
│  ├─ ai/           敌方 AI
│  ├─ script/       事件脚本解释器
│  └─ tools/        表格→JSON、占位美术生成、图集打包
├─ assets/          美术 / 音频（按许可证分目录）
├─ maps/            Tiled 工程与导出 JSON
└─ tests/           Vitest 单测 + Playwright 自动试玩
```

## 6. 系统设计初稿（简化公式，先跑起来再调）

以下是为了让程序先动起来的第一版规则，数值全部可调。原作精确公式需要拆包逆向，我们不照抄，只保留手感。

### 6.1 命中

```
有效命中 = min(驾驶员命中 + 武器命中修正, 机体限界) + 精神 / 技能修正 + 攻方地形适应修正
有效回避 = min(驾驶员回避 + 机体运动性, 机体限界) + 守方地形回避修正 + 精神 / 技能修正
命中率   = clamp(有效命中 − 有效回避 + 尺寸修正, 0, 100)

尺寸修正：目标每比攻方小一级，命中 −10%
精神：必中 = 100%；闪避 = 本次 0%；集中 = 命中 +30 且 被命中 −30（本回合）
反击选项：选「回避」时敌方命中率 ×0.5
```

### 6.2 伤害

```
地形系数：A = 1.0, B = 0.8, C = 0.6, D = 0.4（武器与机体适应取较低者）
攻击值 = 武器攻击力 × (攻方气力 / 100) × 地形系数(攻) × 精神倍率(热血 2.0 / 魂 3.0)
防御值 = 机体装甲 × (守方气力 / 100) × 地形系数(守) × 地形防御修正
伤害   = max(攻击值 − 防御值, 最低伤害 10)
修正   = CT ×1.5（CT 率 = 技量差 + 武器 CT 修正）；选「防御」×0.5；铁壁 ×0.25
       光束武器遇 I 力场 / 光束涂层：固定减免或无效化（阈值可调）
```

### 6.3 气力

```
初始 100（个别角色 105–120），范围 50–150
命中 +1 ｜ 回避 +1 ｜ 被弹 +1 ｜ 击坠 +3 ｜ 友军被击坠 +1（主角 +2）
气合 +10 ｜ 激励 对象 +10 ｜ 脱力 对象 −10
武器需要气力：普通 100，强力 110–120，必杀 130
```

### 6.3b 神通（原精神指令，2026-10-07）

消耗神识（SP，每关满额，不随回合恢复），只影响使用者自己。「本回合」= 持续到使用者阵营下一次行动开始。

| 神通 | 对应 SRW | 神识 | 效果 | 持续 |

| 凝神 | 集中 | 15 | 命中 +30、被命中 −30 | 本回合 |
| 破妄 | 必中 | 20 | 攻击命中率 100%（对方身法时仍为 0） | 本回合 |
| 身法 | 闪避 | 15 | 下一次被攻击必定回避（优先于破妄） | 被攻击一次 |

## 7. 风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| 像素美术产能不足 | **最高** | 占位先行；买素材包过渡；演出帧数做最简版；换色复用；尽早定像素师 |
| 版权 | 高 | 全原创机体与角色；避免「高达」「魔神」等名称与剪影；字体 / 素材只用 OFL / CC0 / 明确商用许可 |
| 范围膨胀 | 高 | 严格 垂直切片 → Demo；分歧路线、合体变形、MAP 兵器、强化零件统一后置 |
| 数值失衡（真实系过强 / 超级系过弱） | 中 | 用脚本批量模拟；限界和尺寸规则可随时调 |
| 网页存档丢失 | 中 | IndexedDB + 导出 / 导入文件 |
| 个人精力 | 中 | 每周固定一次 review 和试玩，Claude 按周出可玩版本 |

## 8. 需要你拍板的 6 件事

1. **平台**：网页优先（推荐）还是桌面优先？
2. **内部分辨率**：480×270（现代宽屏）还是 320×240（原作味）？
3. **项目名 / 世界观方向**关键词（例如：近未来地球 vs 宇宙殖民地；超级系与真实系混编）。
4. **美术路线**：A 找像素师 / B 先买素材包 / C 先全占位做到垂直切片再说（推荐先 C 再 A，两者可并行）。
5. **范围**：先做垂直切片（推荐）。
6. **是否现在开始**搭工程骨架 + 占位美术 + 第一张图。
