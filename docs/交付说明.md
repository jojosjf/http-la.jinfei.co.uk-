# 交付说明：第一版

## 1.0.1（安卓市场发布版）

在 1.0 的基础上只修了两处拖动时的抖动，没有新功能：

1. **拖线时线跑得比手指快、来回乱跳**：原来把每次移动事件的位移累加，平台重复发送移动事件时（鸿蒙模拟器用鼠标时实测约 2 倍）线会多走。现在按“手指离按下点多远”计算线的位置。新增测试模拟重复的移动事件。
2. **“临界”提示出现或消失时图片跳动**：空行和中文在有些系统上字体不同、行高不同，结果栏会变高变矮。现在提示行和数值格都是固定高度。

版本号 1.0.1（versionCode 2）。自动识别、测量记录、结果图、底部导航等新功能保存在 GitHub 分支 `version-1.1`，以后可以从那里继续。

测试中发现并修复了一个严重问题：旧版在手机上一选图就崩溃（解码器生命周期错误，见提交记录）。

**PNG 在模拟器上读不出来**：用不含本项目任何代码的最小 Flutter 程序对照测试，同样报 `Could not decompress image`。
所以这是 Flutter 引擎在纯软件模拟的 x86_64 模拟器上的问题，不是本项目的代码问题。
真实手机是 ARM 架构，引擎走不同的解码路径，**需要在真机上确认 PNG（包括手机截图）能否正常打开**。

**未验证**：安卓真机、iOS、鸿蒙都没有实际运行过；双指缩放在模拟器上无法用命令模拟多指操作，只在网页版上验证过。

## 假设与文档不一致之处

### 需求与交互
1. **产品文档的测试用例表没有拿到。** 现有测试是按实施说明自行编写的，拿到后需要逐条补入 `test/centering_test.dart`。
2. **手柄**：每条线一个深色半透明标签，里面是“双框”小卡片图示（用线的颜色高亮这条线要对准的那一条边），旁边写“外左”“内上”等（英文界面为 OL、IT 等）。标签按边归组放在每条边的中间：外框标签在线的外侧，内框标签在线的内侧。标签会压在照片上；卡片贴近照片边缘、外侧放不下时，外框标签会被推回屏幕内并盖住一段线。放大后标签沿线移动，始终完整留在屏幕内。外框线为长虚线，内框线为短虚线，空隙露出底下的卡片边缘。图片按屏幕能容下的最大尺寸显示，四周不再预留手柄区。
3. **放大镜跟随手指**：放大被拖动的线上与手指对应的那一点——拖左右两边的竖线时取手指的高度，拖上下两边的横线时取手指的水平位置；手指沿线方向移动只换放大的地方，不改变线的位置，可以沿线逐段检查。放大镜显示在手指上方 80 点，上方放不下时改到下方。拖线期间隐藏所有手柄标签，放大镜里只有照片和线，松手后标签恢复。
4. **拖动也会选中该线**，松手后可以直接用箭头微调。
5. **最外侧的线不能超出图片边界**（文档只规定了线之间的顺序）。
6. **微调栏和临界提示始终占位**：没有选中线时微调栏显示操作提示；临界提示那一行没有临界时留空。否则这两处出现或消失时画布高度会变，图片会跳动。
7. **旋转（新增，原文档没有）**：微调栏右侧“旋转”按钮打开刻度盘，左右拖动可在 ±180° 内任意旋转，精度 0.1°，有归零、完成按钮。图片绕中心旋转，超出原图范围的部分裁掉；参考线不随图片转，用户把歪斜的卡片转正后对齐。旋转不影响已摆好的线和微调精度（仍为 1 个原图像素）。
7a. **免责说明**：结果栏底部缩为一行小字（“参考 PSA 公开标准，仅供参考，与 PSA 无关联”），去掉“仅测量正面”；完整说明在“说明”里，并注明参考等级按 PSA 正面标准计算（背面标准更宽松，用于背面时只有比例可作参考）。
7. 等级低于 PSA 3 时显示“低于 PSA 3”。临界提示只针对 PSA 7–10，与文档一致。
8. **默认中文**：只有英文系统显示英文，其他语言（包括繁体中文、日文等）一律显示简体中文；安卓桌面应用名同样默认中文。

### 图片处理
9. 系统选图器会把图片复制到 App 的临时目录；读取完成后立即删除这份副本，只删临时目录里的文件。
10. 超过 1200 万像素的图，手机端在解码时直接缩小，由引擎在后台线程完成，没有另开 isolate。
11. 网页端无法边解码边缩小，大图会完整解码：在无 GPU 的测试浏览器里，4800 万像素约需 6 秒，真机浏览器上未测。
12. HEIC：手机端依赖系统解码器，未在设备上验证；网页端只有 Safari 支持，其他浏览器会提示换 JPG 或 PNG。

### 平台与上架
13. **新增网页版**（原文档没有）：内置中文字体子集，不依赖谷歌 CDN 和谷歌字体。
14. **应用图标是占位图**，需要替换成正式图标后重新生成。
15. **iOS 中文显示名未配置**：目前所有语言都显示 “Card Centering Check”。需要在 Xcode 里给 Info.plist 添加 zh-Hans 本地化（InfoPlist.strings，设置 `CFBundleDisplayName = "卡牌居中检查"`）。在没有 Xcode 的情况下手改工程文件风险太大，所以没有做。
16. 包名按建议用了 `com.saod.cardcentering`（安卓和 iOS 一致），**待确认**。
17. Google Play 版（AAB）按原文档构建了，是否上架待定。**没有使用文档中的 `--flavor googleplay/china`**：两个版本本来完全相同，而 flavor 要求 iOS 也配套 Xcode scheme，否则 iOS 无法直接运行；现在国内版用 `flutter build apk`，Google Play 用 `flutter build appbundle`。
18. 国内版没有声明谷歌的 Photo Picker 后移服务：没有谷歌服务的机型会回退到系统文件选择器，未在真机验证。
19. 签名：生成了 JKS 格式的上传签名文件，别名 `upload`，有效期 10000 天，已单独交付，**不在仓库中**。

### 鸿蒙兼容（鸿蒙版 Flutter：gitcode CPF-Flutter/flutter_flutter）
20. 同一份代码已用官方 Flutter 3.47.5、3.35.7、3.27.4 分别验证：分析无问题、全部测试通过。对应鸿蒙版分支 `oh-3.35.7-release`（需要较新的 HarmonyOS SDK，模板目标 26.0.0）和 `br_3.27.4-ohos-1.0.4`（适合 API 22 左右的 SDK）。
21. 为兼容旧版本：Dart 要求 `^3.6.0`，`image_picker ^1.1.2`，`flutter_lints ^5.0.0`；测试中的矩阵用 `Matrix4.diagonal3Values` + `setTranslationRaw` 构造。新版 Flutter 仍会用最新依赖。
22. 鸿蒙端还需：用鸿蒙版 Flutter 生成 `ohos/` 目录；`image_picker` 用 dependency_overrides 指向社区鸿蒙适配版（3.35 用 tag `image_picker-v1.2.1-ohos-1.0.1`，3.27 用 `image_picker-v1.1.2-ohos-1.0.1`）；改 `ohos/build-profile.json5` 的 SDK 版本、`AppScope/app.json5` 的包名；配置鸿蒙签名。上架前删掉 `module.json5` 里模板自带的 INTERNET 权限。
